01 · 设计哲学与硬约束

极简灰白 · 克制 · 信息优先

参考 Notion / Linear / Apple 风格。所有界面遵循以下不可妥协的底线，避免「AI 生成感」。

视觉底线
  • 背景以白 #ffffff 为主，层次靠 --bg-2/-3 与细线 --line 区分，不靠阴影堆叠。
  • 禁止纯黑：文字主色 --fg:#1c1c1e，绝不写 #000。
  • 色板 ≤ 3 核心（蓝 / 灰 / 紫·元神）+ 1 强调（蓝）；状态色仅 成/警/危/信息。
  • 禁用大渐变、禁用过度动画、禁用玻璃拟态（glassmorphism）滥用。
  • 留白充足（间距尺度 --sp-*），一屏只突出一个主操作。
文案底线
  • 直述、克制，不堆砌标语与 emoji。
  • 按钮用动词（开始 / 生成 / 导出），不用「点击这里」。
  • 危险操作用 confirm 二次确认；轻提示用 toast。
  • 状态用「面（surface）」持续展示，不靠刷屏日志。

05 · 反「AI 废话」检查清单（Shipping Gate）

每次出 UI / 原型前逐条过。任一命中即打回。

  • ✕
    禁纯黑：任何 #000 / black 文字或背景 → 改用 --fg:#1c1c1e / --gray-900。
  • ✕
    禁大紫渐变 + 玻璃拟态套餐：主色只用蓝/灰/紫(元神)，不用 linear-gradient(135deg,#a78bfa,#ec4899) 这类网红渐变。
  • ✕
    禁色板爆炸：核心色 ≤3 + 1 强调；状态色限定 成/警/危/信息 四组。
  • ✕
    禁硬编码 hex 散落：组件里出现 #fff/#f5f5f7 等即违规，必须引用令牌。
  • !
    禁过度动画：除 toast / 状态点呼吸外，避免入场飞入、视差、无限旋转。
  • !
    禁信息过载：一屏一个主操作；次要信息收进折叠 / 次级背景。
  • ✓
    令牌引用率：前端 var(--*) 引用 > 0 处未定义；改色只动 :root。
  • ✓
    字面直述：文案说人话，动词开头，无「赋能 / 一站式 / 颠覆」类空话。
06 · Agentic UI 2026 模式要点

分身是「群聊形态的 AI 团队总管」，界面要服务于「元神调度 + 人监管」，而非聊天机器人。

1持久状态面

把「正在做什么 / 进度 / 下一步」常驻在状态面，取代滚动聊天记录。用户一瞥即知全局。

2检查点确认

高利害操作（删除项目、外发、付费）必须 checkpoint 二次确认，不能「自动执行」。

3实时思考视图（浓缩）

元神推理过程以浓缩摘要呈现（非逐 token 流），可展开看细节，避免信息噪声。

4中断与重定向

用户随时可打断、改指令、纠正；调度器实时接管，不锁死流程。

5运行后摘要 + 出处

任务结束给结构化摘要（做了什么 / 产出 / 引用来源），而非一大段流水账。

6三栏 / 两栏半布局

「对话」与「工作区（看板/文件/状态）」分离；群聊=左栏项目，中栏对话，右栏执行直播。

07 · 令牌单一真源规则（Golden Rule）
真源：frontend/index.html 的 :root 是唯一权威令牌定义。
本页 :root 只是「文档快照」，供原型 / 离线参考。改令牌流程：
① 改 frontend/index.html 的 :root → ② 跑 scripts/bump_version.py 升级版本（含 smoke 门禁）→ ③ 同步本页 :root。
严禁在别处（组件 / 内联 style / 新页面）重新定义或硬编码色值、字号、间距。

版本真源：backend/version.py → /api/version 暴露 SEMVER / RELEASE / SCHEMA_VERSION / BUILD_DATE / COMMIT。 CHANGELOG 见仓库根 CHANGELOG.md。
