# 分身 · 六能力基线档案（v1）

> 建立日期：2026-09-05　基线版本：**0.64.60**
> 用途：**六能力 = 分身产品状态的唯一评判口径**。后续所有开发规划、每轮检测、每次发布，一律按这六项能力的等级变化来评判，不再以「做了几个功能」论进展。

## 1. 六能力是什么

| 编号 | 能力 | 一句话定位 | 为什么算一种「能力」 |
|---|---|---|---|
| **D0** | **大模型能力** | 连得上、记得住、用得省、坏不了 | 信任底线。Key 记不住 / 静默失败 = 产品不可用 |
| **D1** | **蒸馏能力** | 把「本机用户本人」蒸馏成可复用的数字分身 | 差异化核心，决定「像不像你」 |
| **D2** | **元神能力** | 理解意图、调度 agent、交付价值、自主推进 | 决定「能不能替你干活」 |
| **D3** | **Skill 模组能力** | 精选、纯 stdlib、可组合、启动即用 | 决定「干活的手段够不够、干不干净」 |
| **D4** | **工程交付能力** | 一键构建、三端产物、质量门禁、可回滚 | 决定「能不能稳定地交到用户手上」 |
| **D5** | **生产稳定性与可靠性** | 常驻守护、原生模块、数据不丢、自愈 | 决定「能不能长期放心用」 |

**等级量表**（L0 最差 → L4 最优，沿用评估标准 v2 通用量表）：

- **L0** 不可用心（或命中宪法红线，整体不通过）
- **L1** 有雏形，主要靠人工/碰运气
- **L2** 可用，主要路径跑通，有基本检测
- **L3** 可靠，自动化 + 可观测 + 有护栏，异常不静默
- **L4** 卓越，分层/择优/成本可视化 + 自优化

## 5. 评判规则（后续一律照此执行）

### 5.1 开发规划怎么排
1. **按门禁缺口排序**：先看有没有能力低于门禁线（**截至 0.75.0，六能力均已达门禁线，无低于线项**；此前唯一的 D5 < L3 已于 0.75.0 P0-b 闭环），缺口项优先级最高。
2. **按宪法红线排序**：任何命中红线的问题，无条件插队到最前。
3. **按「未量化」排序**：标注「未测/未量化」的检测项，优先于「已达标但要锦上添花」的项 —— 没有数据就无法评判，这是 D2 长期停 L2 的根因。
4. 不做与六能力无关的功能堆砌。

### 5.2 每轮检测怎么评
1. **D0 先测**（信任底线，不过则阻断全量）。
2. **D5 再测**（地基）。
3. **D4 门禁**（smoke + 构建）。
4. **D1/D2/D3 抽样评测**（有评测集的用集，没集的先建集再评）。
5. 出结论时**只报六能力等级变化**，不报功能数量。

### 5.3 发布门禁
```
放行条件 = D0 ≥ L3  且  D5 ≥ L3  且  D1~D4 ≥ L2  且  宪法红线 0 命中
```
不满足时的处置：
- **D0 < L3** → **阻断全量**（信任底线不可妥协）。
- **D5 < L3 但 ≥ L2** → 有条件放行，须在评估卡写明遗留风险与补齐时点。
- **任一能力命中红线** → 整体不通过，与等级无关。
