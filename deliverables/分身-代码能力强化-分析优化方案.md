# 分身 v1 · 代码能力强化：现状分析 + 业界对标 + 优化方案

> 定位：本文是「分模块强化」中**代码功能（核心能力）**专项的分析与设计稿。
> 目标：基于已有成果，分析可改进方向 → 对标业界出色代码 Agent → 提出可落地的优化方案。
> 日期：2026-08-18 | 分支：`fix/v4.0-audit`

---

## 0. 一句话结论

分身系统**最稀缺的不是「生成代码」，而是「可靠地验证与自愈代码」**。我们有业界没有的元层资产（元神宪法 / 类脑自进化5环 / 8态状态机 / 多角色持久团队），但核心代码管线的**沙箱验证、自纠正闭环、确定性质量门、代码库语义理解、代理级版本管理**是缺口。优化方向不是复制 Claude Code/Codex，而是**用我们的元层「包裹」业界已验证的执行纪律**，并把自进化闭环接入代码——这是我们能赢过通用代码 Agent 的差异化杠杆。

## 1. 现状基线（基于已有成果）

### 1.1 我们的独特资产（业界代码 Agent 没有的）

| 资产 | 说明 | 与代码能力的关系 |
|---|---|---|
| **元神宪法** | 元神绝对站在本机用户利益一边（5条） | 代码护栏的「价值锚」：生成代码不得损害用户账号/隐私/资产 |
| **类脑自进化5环** | 蒸馏 / 熔断 / 成员经验进化 / 磨压缩 / 疗效归因 | 跨项目、跨会话的**持久学习闭环**——业界代码 Agent 完全没有 |
| **8态状态机 + 事件溯源** | 权威状态 + 守卫转移 + `meta_state_log` | 代码任务的**可观测/可管控**治理面 |
| **多角色持久团队** | 角色成员带经验、可升级（`_auto_upgrade_member`） | 类似 Devin 子任务的「持久化」版——成员会越用越强 |
| **质量门基建** | `smoke_v40.py`(76断言) + `bump_version.py`(fail-closed) | 已具备确定性门禁**骨架**，但目前只人工跑、未接进 Agent 流 |
| **疗效归因 5维权重** | 经验库聚合权重 + 弱项补强 | 独有信号：让「什么代码模式有效」可被量化、召回 |

### 1.2 当前代码管线（已落地的真实链路）

```
用户/群聊 → /api/projects/{pid}/chat
  → _execute_project_chat：元神用 dispatch_sys 提示输出 JSON 调度计划(actions)   [main.py 5325-5377]
  → _run_one：每个 action 建看板卡 → 派给 backend/frontend/tester 等角色        [main.py 5395/5540]
  → _chat_with_tools：角色用 function calling 调 write_file 写代码到 modules/<mid> [WRITE_FILE_TOOL 3837 → _write_file_tool 4085]
  → verify_task / _judge_role_output：纯 LLM 文本判定对照 done_criteria       [main.py 6628 / 5035]
```

模型层：`call_llm`(1519) → `_call_single_provider`(1384，同步 HTTP，无流式)；backend=deepseek-v4-flash，frontend/tester=gpt-4o-mini，失败按 `FALLBACK_ORDER` 降级。

### 1.3 缺口（来自代码探查的 GAP 分析）

| 维度 | 状态 | 关键位置 | 后果 |
|---|---|---|---|
| **沙箱验证** | ❌ 缺失 | 仅 LLM 文本判定 `5035/6628`；`exec_command` 需人工审批 `3928` | 不自动跑/测代码，错误靠"猜" |
| **自纠正闭环** | ⚠️ 部分 | 重规划 `5585-5592` + 熔断 `8083`；无 run→error→fix | 代码报错不自动修，靠"再派一版" |
| **代码库理解** | ⚠️ 部分 | 文件名检索 `3675` + 爆炸半径切片 `5476`；**无 embed/向量** | 改代码易漏下游依赖、易幻觉 API |
| **代理级 VCS** | ❌ 缺失 | git 仅黑名单 `1885-1892`，无 branch/commit | 无原子回滚、无 PR 评审 |
| **确定性质量门** | ⚠️ 部分 | `done_criteria` LLM 判 `5035` + 版本冻结 `6658`；无 lint/typecheck/test | 验收主观、"绿了"≠能跑 |
| **角色级规划门禁** | ⚠️ 部分 | 元神 JSON 计划 `5325-5377`；角色层无强制 plan-before-code | 角色可能直接动文件 |
| **LLM 代码生成** | ✅ 存在 | `write_file`+`call_llm`；但无流式、单轮、无代码质量系统约束 | 长任务易断、易编造 API |

## 2. 业界对标（2026 主流代码 Agent）

### 2.1 横向矩阵

| 维度 | Claude Code | OpenAI Codex | Cursor | Devin |
|---|---|---|---|---|
| 形态 | 终端 Native | 云端 Native | IDE Native | 全流程云 SWE |
| 核心循环 | 读→计划→改→**跑测试→修→提交** | 沙箱 VM 异步跑→**自动 PR** | Agent/Composer 多文件改→跑命令→迭代 | 计划→写→**测→调试→PR** |
| 沙箱/验证 | ✅ 权限沙箱 + test_loop | ✅ 沙箱 + 自动验证 | ✅ 云 VM 跑测试 | ✅ VM+browser+editor |
| 长程能力 | 1M 上下文；Managed Agents 检查点 | 压测 25h/13M tok/30k LOC | 并行至多 8 隔离分支 | 并行子任务 + Kanban |
| 规则/锚点 | CLAUDE.md | CLI flags | .cursor/rules/*.mdc | — |
| 多代理 | Subagents + Routines | 管理器协调并行 worktree | Agents Window 并行 | Devin Local 子代理 |
| 独有 | MCP 生态深 | 内置安全层 Codex Security | Bugbot 每 PR 自动审 | 完全自主、Kanban 指挥中心 |

### 2.2 它们"可靠"的共识做法（来自最佳实践文献）

1. **验证优先 / Plan-before-code 门禁**：动文件前先产出书面计划（改哪些文件、风险、依赖），人审或自动门禁通过才执行。
2. **TDD（RED-GREEN-REFACTOR）**：先写失败测试→最小实现→重构；测试即规格。
3. **沙箱 run→verify→fix 闭环**：agent 自己编译/跑测/读错/修/再跑，直到绿；设边界防无限自调试烧 token。
4. **确定性质量门**：compile + lint + typecheck + test **必须过**，不靠 LLM 文本判。
5. **代码库锚点文件**（CLAUDE.md / AGENTS.md / .cursorrules）：把构建命令、测试命令、代码风格写成机器可读契约。
6. **diff-bounded 改动**：约束最小 diff，限制爆炸半径、让幻觉显形。
7. **交叉验证 / 写测分离**：一个写实现、另一个写测试对照需求（"校验式开发"）。
8. **人类终审 + 风险分级**：低风险脚手架放手干，高风险先设计文档+威胁评审。
9. **代理级 VCS**：分支隔离、提交、PR，长任务可检查点续跑。

## 3. 差异化定位：我们 vs 它们

```
它们强在：执行可靠性（沙箱/测/修闭环、语义索引、VCS、sub-agents）
我们强在：元层与学习（宪法护栏、自进化5环、经验归因跨项目、多角色持久团队、状态机治理）

→ 我们的策略：不复制它们的"终端 Agent"，而是把它们的"执行纪律"
  接进我们的元层，并让自进化闭环吃进代码经验。这是差异化胜点。
```

**我们独有的、可转化为代码优势的杠杆：**
- 疗效归因 5维权重 → 让"哪种代码模式/修复有效"可量化、可召回（它们没有持久学习）。
- 多角色持久团队 → 写/测角色可**长期**分工协作、越用越准（Devin 子任务是临时的）。
- 元神宪法 → 代码护栏的价值锚（账号归属、不泄露、不破坏）。
- 质量门基建已就绪（smoke/bump）→ 只需"接进 Agent 流"即可升级为确定性门。

## 4. 优化方案（10 个方向，按杠杆排序，均映射到已有资产）

### D1 · 沙箱验证闭环（最高杠杆，补最大短板）⭐⭐⭐
- **目标**：代码改动后自动在隔离环境编译/跑测/读错，绿了才算完成。
- **改动点**：基于现有 `_exec_shell_tool`(3451) 扩出**每任务沙箱**（venv/容器，cwd=模块工作区，自动放行代码类命令）；把 `pytest`/`lint`/`py_compile` 接进 `verify_task`(6628) 取代纯 LLM 判定。
- **收益**：直接消除"绿了但不跑"的核心风险。
- **复用**：`exec_command` 已有、`smoke_v40.py` 是现成测试入口。
- **护栏**：设最大验证轮次（沿用 `FAIL_BREAKER` 思路）防烧 token。

### D2 · 角色级 Plan 门禁 ⭐⭐⭐
- **目标**：角色动文件前必须先产出计划（文件清单/方案/风险），门禁通过才写。
- **改动点**：在 `_chat_with_tools`(5540) 提示中强制"先 plan 后 code"；dispatch actions 增加 `plan` 类型，需确认再转 `code`。
- **复用**：元神级 JSON 计划 `5325-5377` 已存在，下沉到角色级。
- **收益**：减少大改回滚、降低幻觉。

### D3 · 确定性质量门（把现有骨架接进 Agent 流）⭐⭐⭐
- **目标**：代码类任务完成 = compile+lint+test 全绿（非 LLM 主观）。
- **改动点**：在 autopilot 派单收尾自动跑 `smoke_v40.py` + `bump_version.py` 的 compile_gate；失败则回退重做。
- **复用**：`smoke_v40.py`(76断言) + `bump_version.py`(fail-closed) 已就绪，仅缺"自动触发"。
- **收益**：把已建的质量基建变成真实护栏。

### D4 · 自纠正 run→error→fix 闭环 ⭐⭐⭐
- **目标**：验证失败时，把错误输出喂回角色→重规划→改→再验，直到绿或触顶。
- **改动点**：`verify_task` 失败时将 stderr/traceback 作为 tool_result 回灌 `_chat_with_tools`；复用 `MAX_ROUNDS`(5390) 与 `FAIL_BREAKER`(8083) 做边界。
- **收益**：从"再派一版"升级为真正的 fix 循环。
- **复用**：`FAIL_BREAKER`、`_recycle_stuck`(8546)。

### D5 · 代码库语义理解（锚点文件 + 轻量检索）⭐⭐
- **目标**：角色改代码前能理解现有结构、依赖、符号，不漏下游、不幻觉 API。
- **改动点**：引入 `AGENTS.md` 式项目锚点（构建/测试/风格契约，可复用我们的项目配置+经验库）；在"爆炸半径"基础上加**符号/依赖检索**（AST 解析 + grep），必要时轻量向量索引。
- **复用**：`search_files`(3675) + 爆炸半径切片 `5476` + 经验库 `_recall_experiences`(7306)。
- **收益**：降低跨文件改动的回归风险。

### D6 · 代理级版本管理（任务分支 + 提交 + PR 评审）⭐⭐
- **目标**：每任务独立分支、原子提交、合并前评审门。
- **改动点**：放开 git 黑名单(1885) 中"安全子集"（branch/add/commit，仍禁 push --force/reset --hard 等）；任务级 worktree/分支；完成后开 PR 式评审再合主干。
- **复用**：`DANGER_RE`(1885) 已是管控点，扩展为"白名单放行"。
- **收益**：可回滚、可审计、符合工程规范。

### D7 · 流式 + 代码专用模型 + 质量系统提示 ⭐⭐
- **目标**：长代码任务不断流、用代码擅长的模型、强约束降幻觉。
- **改动点**：`call_llm`(1519) 增流式（SSE）；`FALLBACK_ORDER`(110) 加代码专用模型；角色系统提示加**代码质量硬约束**（禁止编造 API、强制类型注解、diff-bounded、加测试）。
- **复用**：`call_llm`/`FALLBACK_ORDER` 现成。
- **收益**：首过质量与长任务稳定性。

### D8 · 多角色交叉验证（写/测分离）⭐⭐
- **目标**：一个角色写实现、tester 角色写测试并跑，双方对照需求交叉验证。
- **改动点**：dispatch 时对代码任务生成"实现动作 + 测试动作"配对；tester 角色基于同一 spec 写测试，与实现对照（"校验式开发"）。
- **复用**：tester 角色已存在；`asyncio.gather`(5569) 已支持并行。
- **收益**：用我们的团队资产实现业界"交叉验证"最佳实践。

### D9 · 疗效归因接入代码（独有胜点）⭐⭐⭐
- **目标**：成功的代码修复模式 + 错误类型回流经验库，5维权重量化，未来同类任务可召回。
- **改动点**：D1/D4 验证"修好"时，把（错误类型→修复模式→验证方式）写入经验库并打 5维权重；后续同类任务 `_recall_experiences` 优先召回。
- **复用**：`疗效归因`(attribution) + `_recall_experiences`(7306) + 5维权重 `_ATTR_W`(7173) 全现成。
- **收益**：**这是我们能赢过通用代码 Agent 的核心**——它们没有跨项目持久学习。

### D10 · 元神宪法代码护栏扩展 ⭐⭐
- **目标**：生成/执行的代码守宪法——不破坏账号归属、不泄露密钥、不越权。
- **改动点**：在 D6 放行的 git 白名单 + `write_file` 越界拒绝(4093) 之上，加**代码静态扫描门**（禁硬编码密钥、禁外联未知域名、禁破坏性系统调用）。
- **复用**：`DANGER_RE`(1885) + 元神宪法 5条 + `write_file` 越界守卫(4093)。
- **收益**：把"价值锚"落到代码层。
