# 分身 · 分模块改进设计方案 v2

> 已消化三张参考图并吸收到本方案。日期：2026-08-18。
> 核心选择：**先落地产品内引导（零外部依赖），官网 fenshen-docs 与外部触发器统一挂起但不遗忘。**

---

## 一、三张参考图的消化与借鉴

### 图1 · AGENTS.md「AI 工程开发原则」

与本产品已有纪律一致：KISS、DRY、SOLID、最小可用、先复用已有能力再新增依赖、从可运行版本逐步演进。

吸收的改进约束（加进本方案每条设计）：
- 每个模块改进前，先检查 backend/main.py / 现有前端 section / 已有 skill / 现有设置键，避免重复造轮子。
- 不为假设中的未来需求提前引入抽象层、配置层、中间层。
- 规则 / 提示词 / 宪法 / 护栏避免冗余重叠；规则越多不等于越安全，重叠与冲突会产生「执行税」。
- 优先用成熟稳定、维护良好的第三方库；若需新增依赖，必须说明「不用现有机制无法实现」的理由。

### 图2 · 长上下文的代价：容量不等于有效注意力

核心启示：上下文越长，模型表现越可能下降（13.9%–85%），成本上升 20% 以上，强模型反而更容易被冗余规则拖累。

对分身的借鉴：
- 上下文预算可视化：在 元神驾驶舱 / 模型设置 增加 token 预算仪表，让用户看到「当前项目上下文用了多少、还剩多少」。
- 压缩透明化：E6 无损归档 + 摘要节点方向正确，但需要在 UI 告诉用户「哪些节点被归档、摘要保留了什么、原始记录仍可回溯」。
- 提示词精简审计：角色 prompt、系统提示、宪法、护栏规则应定期审计，删除重复或冲突项。
- 冲突裁决可视化：当经验晋升 / 淘汰、蒸馏授权、宪法之间出现冲突时，系统需明确裁决并展示依据。

### 图3 · Hermes 主动化配置的 10 个操作

可直接借鉴到分身模块的设计：
- 总控面板可视化 Agent 状态 -> 元神驾驶舱增强：agent 状态卡、进度条、成功率、当前任务列表。
- /goal 标准化目标格式 -> 项目目标 / 完成标准向导强化，支持在群聊输入 `/goal` 快速查看或修改项目目标。
- 三个子 Agent 并行组成研究团队 -> 已在产品中，需在驾驶舱 / 看板可视化「哪些 agent 正在并行、谁在等谁」。
- Telegram 话题分组 / 独立工作区 -> 项目分组 / 标签、上下文隔离增强。
- 看板管理多任务一目了然 -> 现有项目看板，可增加经典泳道视图（Backlog / In Progress / Review / Done）。
- 重复流程固化成 Skills -> 技能库增加「从本次对话 / 工作流生成技能」入口。

需要外部依赖、本期挂起的灵感（记录但不落地）：
- Notion 工作流：数据库变化自动触发任务。
- Cron 定时任务主动推送：Telegram / Email / Notion / Webhook。
- Webhook 事件驱动：监听外部事件触发 agent。
- 按工种分配不同模型与权限：角色库可扩展，但「不同模型」依赖模型路由能力先到位。

## 二、使用引导落地选择

### 选择：先落地「产品内引导四件套」，官网 fenshen-docs 挂起到 Phase 2

理由：
- 产品内引导零外部依赖，可立即基于现有 wizard / window._tour / about 扩展。
- 新用户上手痛点最痛：先解决「进产品后不知道点哪里」。
- 官网需要域名、部署、内容同步机制，属于外部依赖，先挂起但不遗忘。

### Phase 1 · 产品内引导（现在做，按顺序）

1. 空状态提示 Empty-state（最高性价比）
   - 为 14 个模块在数据为空时显示：一句话说明 + 第一句该做什么 + 一个主按钮。
   - 例：经验库空 -> "经验库是元神踩坑/成功经验的沉淀。当前 0 条，开启进化开关后自动积累。"
2. 帮助中心 Help Hub
   - 把「关于分身」扩展为「帮助中心」tab：搜索 + 分模块短文 + 跳转官网（链接先占位，等官网上线后替换）。
3. 首用向导增强
   - 复用 v5.1 软门槛 + 项目向导，首次启动增加「一键成立第一个项目」入口。
   - 落库 meta_settings.onboarding_done=1，可跳过，可重置。
4. 分步导览 Guided Tour
   - 扩展现有 window._tour，为核心模块配置 3–5 步高亮气泡：对话群聊 / 项目看板 / 元神驾驶舱 / 角色库 / 蒸馏 / 进化中心。

### Phase 2 · 官网 fenshen-docs（挂起，待外部条件）

- 独立静态站（推荐 VitePress），信息架构沿用上一版方案：首页 / 快速开始 / 概念 / 模块指南 / 进阶 / 教程 / API / FAQ / 更新日志 / 安全隐私。
- 挂起原因：需要确定域名 / 子路径、部署流水线、内容从 IN_APP_GUIDE 同步的机制。
- 启动条件：域名或子路径确定、且能安排一次独立部署任务。

## 四、设计约束与落地纪律（吸收图1 + 既有工程规范）

1. 每条改进必须先回答：
   - 现有代码 / section / skill / 设置键是否已能支持？
   - 是否引入新的外部依赖或上线阻塞项？
   - 是否增加新的持久化表/列？若有，需迁移脚本与版本 bump。
2. 所有新增 UI 复用 fenshen-v1 设计令牌（:root 变量），禁纯黑、禁大紫渐变、禁硬编码 hex。
3. 所有新功能默认关 / 可跳过，保持零侵入（与 code_* / evolution_* / memory_* 开关一致）。
4. 每次改动走隔离副本 8011 + smoke_v40 + bump patch + 备份 + 平滑重启。
5. 提示词 / 宪法 / 护栏规则有新增时，需同步做「规则冲突检查」：避免与已有规则重叠或矛盾。

## 五、下一步可执行清单（Phase 1 落地顺序）

按此顺序推进，每个任务完成后可独立验收：

1. **IN_APP_GUIDE 内容清单**（JSON/JS 常量）：为 14 个模块写 empty-state 文案 + 帮助中心短文。
2. **空状态提示组件**：在前端各 section 为空时渲染，文案读 IN_APP_GUIDE。
3. **帮助中心 Help Hub**：扩展「关于分身」为「帮助中心」tab，含搜索与模块索引。
4. **首用向导增强**：meta_settings.onboarding_done + 一键成立第一个项目入口。
5. **分步导览**：扩 window._tour，覆盖 6 个核心模块。
6. **P0 模块 UI 实现**：
   - 长期记忆浏览器面板
   - 经验库明细 + lineage 图
   - 蒸馏 subject / 授权管理 UI
   - 元神驾驶舱仪表盘增强
