# 分身 · 模型路由与复杂度分类器 设计 v1

> 版本：0.64.21 待发 | 状态：骨架已落地（后端），前端展示与多 Key 配置待做
> 触发：用户洞察「单模型多 agent = 角色扮演，token 并不更省；真正的群聊 = 多个大模型」

---

## 一、结论先行（先给答案）

**用户判断正确，但有一处需要修正：**

| 维度 | 现状（0.64.20 实测核实） |
|---|---|
| 多 agent 执行 | ✅ **是真的**。元神先调度（1 次 LLM）→ 对每个 action 角色**分别发起独立 LLM 调用**（各自的 system prompt），并发上限 3，带质量门/判定/重规划 |
| 多模型 | ❌ **默认不是**。所有角色走同一个 `deepseek-v4-flash` + 同一个全局 key（`model_configs` 表默认空 → 全部回退） |
| token | ⚠️ 单模型多 agent 的 token **通常更多**（每个角色重复携带项目上下文），并非"差不多" |

**因此**：当前形态 = 「真·多 agent 执行链 + 单模型角色扮演」。要变成「真·多模型群聊」，缺的不是执行循环，而是 **模型注册/路由层 + 每个角色/成员可绑定的独立 key**。

## 二、现状核实（代码证据，main.py）

- 建表：`model_configs`(agent_id, provider, base_url, api_key, model_name) @ **L771**，**无种子数据**
- 成员表 `agent_members.model_cfg`(TEXT JSON) @ **L1168**：默认 `{"model":"deepseek-v4-flash","temp":0.3,...}`，**执行链从不读取**（仅成员 CRUD/进化用）
- 统一调用：`_chat_with_tools` @ **L4954** / `call_llm` @ **L1595** → `_available_providers(agent_id)` @ **L1511**
- 候选链：① 角色自有 model_configs → ② 全库其他角色 key（FALLBACK_ORDER）→ ③ 本地 Ollama → ④ DeepSeek secret 兜底（L1563）
- 执行链 `_run_one` @ **L6301**：用 **role 名**作 `agent_id`，成员 `model_cfg` 不参与
- `ROLE_MODEL_RECS`（architect→claude 等）@ **L114**：**仅 UI 展示，从未用于真实选模**

**关键脱节**：成员级模型绑定（model_cfg）与执行链完全断链；模型选择粒度只能到"角色"，且默认全回退单模型。

## 三、设计

### 3.1 模型注册/路由抽象（本次已落地）

新增「模型注册与路由层」@ main.py L1394 起：

```
_member_model_override(model_cfg_str)  # 成员 model_cfg → (provider,base,key,model) 或 None
_resolve_member_model(conn, pid, role) # 角色当前激活成员 → (member_id, override)
get_model_strategy()                    # roleplay(0~1 供方) / multimodel(≥2 供方)
_available_providers(agent_id, member_override=None)  # 成员覆盖排第一，全局链兜底
_chat_with_tools / call_llm             # 透传 member_override
```

**路由优先级**（成员已绑定专属模型时）：
`成员 model_cfg 覆盖 > 角色 model_configs > 全库其他角色 key > Ollama > DeepSeek secret`

**缺 key 自动回退**：成员未绑定 provider+key（绝大多数默认如此）→ override=None → 走原全局链 → 单模型角色扮演。**行为零回归。**

### 3.2 元神复杂度分类器（本次已落地）

调度 JSON 新增字段：`"team_mode": "single" | "multi"`，与既有 `tier`(0/1/2) 配合：

| tier | team_mode | 含义 |
|---|---|---|
| 0 | - | 即时问答，元神直答，不建卡不派单 |
| 1 | single | 单点/明确小任务 → **只派一个角色**（聚焦、省 token） |
| 2 | multi | 需跨职能协作（设计+编码+测试）→ 拆多角色 |

提示词新增复杂度→调度模式指引（L6164 起），元神输出 `team_mode`，运行结果与轨迹事件携带 `model_strategy` 与 `team_mode`，诚实标记本次是 roleplay 还是 multimodel。

### 3.3 本次顺手修复

1. **元神 JSON 偶发截断**（实测复现：输出 439 字符缺 `]}`）→ 新增 `_parse_dispatch_plan`（括号栈补全重试），主调度与重规划共用；
2. **成员解析时序 bug**：role_start 轨迹事件先于解析执行 → UnboundLocalError，已上移修复。
